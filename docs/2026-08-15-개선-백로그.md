# 개선 백로그 (2026-08-15 정리)

실운영 피드백(카카오톡)·자동대진 리뷰에서 나온 할 일. **앱(Flutter) / 웹(Django) / 교집합(서버 API)** 으로 구분.
사이트=Django(Python), 앱=Flutter로 스택이 나뉘어 있어, 기능마다 어디서 만드는 게 유리한지 함께 표기.

## 아키텍처 방침 (이식 비용 줄이기)
- **로직은 Django API(공용)** — 비즈니스 규칙(정원·승인·매칭·쪽지 발송 대상)은 전부 서버 API. 클라(웹·앱)는 소비만.
- **관리·복잡·드문 화면은 웹 + 앱 WebView 재사용** — 대진 콘솔(`static/match_console`)이 이미 이 패턴. 웹으로 한 번 만들고 앱은 WebView로 열면 앱 재빌드 불필요.
- **참가자가 자주 쓰는 핵심 화면은 Flutter 네이티브** — UX·성능(내 경기·알림·쪽지 뱃지·모임 상세).
- **신규 기능은 API 우선 설계** → 앱 이식이 "화면만 붙이기"로 축소.

## 🔗 교집합 (서버 API — 신청·정원·쪽지·권한)

1. **성비(성별 정원) 설정 버그** 🔴 최우선
   - 성별 정원을 설정해도 저장/적용이 안 되고, 초과 신청이 대기로 안 넘어감.
   - **7/28·8/5 두 번 재발** — 실운영에서 유일하게 반복된 버그.
2. **신청+입금 완료했으나 명단·대기에 안 뜸**
   - 알림은 갔는데 참가 대기에 이름 없음 (8/4 정홍재 케이스). 신청 처리 누락 의심.
   - ※ 지난번 "세션 스냅샷 후 승인자 미동기화(ensure_session)"와 원인 닿을 수 있음 → 착수 시 같이 점검.
3. **쪽지 발송 대상 확대** ✅ 완료(8/24, 배포 대기)
   - `band_schedule_notice_send`의 개별 발송 대상에 `pending`(승인대기/입금전) 추가 → approved·waiting·pending 모두 발송 허용. (rejected·cancelled는 제외 유지)
   - ⚠️ 전체 발송(recipient 없이)은 여전히 approved만 — 대기·승인대기 일괄 발송 필요 시 추가.
4. **모임·동호회·센터 관리자 권한 & 번개 생성 안됨**
   - 센터 번개 생성 포함. 관리자 권한 판정/생성 로직 버그.
   - (지난 18항목의 "1. 센터 번개 생성 안됨"을 포괄)
5. **급수 범위 통합 정원** (신규 기능)
   - 현재: 급수별 **개별** 정원 (A조 10명 / B조 15명).
   - 추가: 급수 **범위 필터 + 통합 정원** — "**B조 이상만 · 총 N명**" (범위 안에서는 배분 자유. 예: AB 합쳐 20명, A14/B6이든 A5/B15든 OK).
   - 설정 UI에서 "급수별 개별 / 급수 범위 통합" 선택. 성비 정원과 구조 맞물림 → 1번과 같이 볼 것.
6. **번개 모집 열기/닫기 시 화면 노출 처리** (검토 필요)
   - 모집을 닫으면(마감) 번개가 목록/화면에서 어떻게 될지 정책 결정 필요.
   - 선택지: (A) 마감 시 숨김 / (B) 목록에 남기고 "마감" 표시·흐림 / (C) 모집만 닫고 상세 유지.
   - 지난번 대회는 "**종료일까지 목록에 남기고 접수만 닫힘**"으로 감 → 번개도 B/C 방향이 일관될 듯.

## 📱 앱 (Flutter — 재빌드 필요, 서버는 데이터/ API만 제공)

7. **참가 대기자 일괄 승인** ✅ 서버 완료(8/25, 배포 대기) — `POST .../applications/bulk-approve/` (application_ids 배열, 신청순 C안 규칙 승인/대기). 정원판정 헬퍼를 단건과 공유. 앱은 화면만 붙이면 됨(응답 message 그대로 표시).
8. **받은 쪽지 안읽음 뱃지/카운트** — 알림 누르면 사라져서 온 줄 모름 → 쪽지함에 `1` 표시 (8/12).
   - **쪽지 상세 화면에도 숫자 띄우기** — 안읽음 개수를 쪽지함 진입 전/후(상세 화면)에서도 노출.
9. **쪽지함 프로필에서 접근** — "프로필 누르면 볼 수 있게" (8/12).
10. **목록 카드 참가신청/공유 UX** — 지금은 목록에서 "참석" 누르고 상세 들어가서 **또 "참석"**(중복). 카드는 **상세 진입만**, 참가신청·공유는 **상세 화면**에 (엔드라인 8/x).
11. **모임 상세 화면 개선** — **포스터 축소** + **클릭 시 전체화면**, **정보가 처음부터 더 보이게**(포스터가 커서 정보 밀림) (엔드라인).
12. **참가자 나이대 표시** ✅ 완료(8/25, 배포 대기) — `UserProfile.age_group`(생년월일 만나이 우선 → 출생연도 → 카카오 age_range). 웹 참가자 명단에 급수와 한 뱃지로(`20 · A조`, 없으면 급수만). 현재 **승인 참가자 명단만** 노출(개인정보). 앱도 age_group API로 붙일 수 있음.
13. **모임 상세 — 현재 참가자 통계 그래프** — 현재 참가자를 **성비·나이대·급수별 원그래프(도넛 등)** 로 시각화. 모집 현황 한눈에.
    - 데이터: 성비·급수는 서버에 있음, **나이대는 항목 12(나이 데이터·개인정보)에 의존**. 차트 형태·항목은 **만들 때 검토**.

## 🎾 자동 대진 (웹 콘솔 — `static/match_console`, 앱은 WebView 재사용 가능)

### ✅ 완료 (2026-08-24 · 로컬 반영, 배포 대기)
- **모드/종목/성향/자동 변경 시 확정 stale 버그** — 종목 바꿔도 옛 종목 `next_lineup`이 남아 꼬임 → 변경 시 무효화+즉시 재계산. (13번 "모드 변경 버그" 실체)
- **리셋 후 오류** — 리셋이 `next_lineup`·`coach_resting` 미초기화 + 종료(ended) 세션은 리셋 자체가 차단됨 → 리셋 시 준비상태로 완전 초기화, 종료 세션도 리셋 허용.
- **준비→시작→종료 3단계 흐름** — 진입 시 `preparing`(코트 빔·추천 숨김), [운영 시작]→`active`, [운영 종료]/1시간 무입력 자동종료→`ended`. 상단 상태바(라벨+안내문구, 높이 고정, SVG 아이콘).
- **성별 미상자 매칭 제외 버그** 🔴 — `is_match_eligible()`이 `overridden` 무시하고 프로필 원본만 봐서, 운영자가 콘솔에서 성별을 지정해도 그 사람이 남복/여복 매칭에서 계속 제외됨(경기 0으로 방치). → override 시 스냅샷 성별로 자격 판정. (실운영 "성별/명단" 문제의 실체)
- **코치 코트 남복/여복 동성 강제 + 남녀 번갈아 + preset** — 남복/여복 모드에서 코치 코트도 동성 3명(코치 무관), 급수 근접 반영, 덜 뛴 성별 우선(번갈아). 시뮬 검증(모수 0%·커버리지 100%·남녀격차 0.7).
- **코치 코트 편집 3버튼 + 출석 기록 코치 이력** — 경기중 코치 코트 [종료]/[편집]/[코치], 편집 모달에 "코치와 안 친 사람" 우선 명단. 출석 기록 시트에 이름·급수·성별 + '👑 코치와 경기'(코치별 만남 N회/아직).
- **상단바·상태바 정비** — 운영 상태바 좌측 텍스트 로고, 우측 [⚙ 설정] 버튼(→ 코트 설정·리셋). ControlBar 아이콘 로고 제거. 종료 안내 문구를 "⚙ 설정 → 리셋"으로 정합.
- **자동↔수동 토글 확정 stale 버그** 🔴 — `set_auto`만 `next_lineup` 무효화가 빠져 있어, 자동 전코트 시작→수동 전환→예약→종료→시작 시 예약이 안 들어감. → set_auto도 확정 무효화(3개 토글 전 조합 검증 0버그).
- **코트 이름 참가자 화면 반영** — `serialize_match`에 `court_name` 없어 이름 변경이 참가자 앱에 안 뜸 → `current_match.court_name` 추가.
- **경기 중 인원 교체 검증 + 2분 룰** — 무작위 교체 500회·API 1800액션 0버그. 교체된(나간) 인원·2분 내 종료는 경기수 카운트X·대기시간 유지(참가자 화면도 반영).
- **매칭 다양성 개선** — window 8→12(모두 모드 커버율 63→77%). 고착은 대기 여유 없을 때만(운영: 코트수 조절)으로 결론.
