## 2. "모두" 모드 종목 분포 분석 (완료)

문제: "모두" 모드인데 혼복이 대부분 나옴 → "모두"의 의미가 약함.

원인: `core.jsx` `disciplinesFor()` 에서 남녀 섞인 4명 조합은 무조건 혼복으로 분류. 남복/여복은 후보 윈도우(상위 9명) 안에 동성 4명이 우연히 모일 때만 가능.

시뮬레이션 (8코트 × 30라운드 = 240경기):

| 설정 | 혼복 | 남복 | 여복 | 개인 경기수 |
|---|---|---|---|---|
| 현재 (bias 끔) | 85.8% | 4.2% | 10.0% | 18~19 |
| bias K=8 | 63.7% | 15.0% | 21.3% | 18~19 |
| bias K=20 | 53.3% | 20.4% | 26.3% | 18~19 |
| bias K=40 | 46.7% | 24.2% | 29.2% | 18~19 |
| bias K=80 | 40.8% | 27.1% | 32.1% | 18~19 |

결론:
- 코드에 이미 있는 `bias`(종목 비율 손잡이)를 켜면 종목이 고르게 분산됨. (`recommendMatch` 5번째 인자)
- 성비(남24:여29) 때문에 정확한 33%씩은 물리적으로 불가능 — 남복이 구조적으로 적게 나옴.
- 현실적 균형 구간: K=40~80.

## 3. "모두" 모드 종목 균등화 (완료)

목표: 3종목 최대한 고르게 (K=80).

변경:
- `core.jsx` `recommendMatchPaired(pool, mode, preset, nowTs, pairs, bias)` — bias 인자 추가, 내부 `recommendMatch` 호출에 전달(기존 누락).
- `app.jsx` `buildBias(s)` 헬퍼 추가: `mode==='모두'`일 때만 `{ counts, target: 균등(1/3씩), K: 80 }` 생성. counts = 완료 경기(participants.games 합÷4) + 진행중 코트 종목.
- `findRec`(추천 표시)·경기 확정 호출 양쪽에 bias 전달. findRec는 같은 라운드 가상 배정분도 counts에 누적해 종목 쏠림 방지.

검증(수정 후 코드 경로, 8코트×30라운드=240경기): 혼복 40.8% / 남복 27.1% / 여복 32.1%, 개인 경기수 18~19.

## 5. "동일 급수" 매칭 개선 — 급수 폭 제한 (완료)

문제: "동일 급수" 프리셋인데 실제론 A급이 D급과 치는 매치가 43%. 프리셋이 팀 간 합 균형(`w_balance`)만 보고 매치 내 급수 동질성은 강제하지 않았음.

분석(시뮬): "완전 동일급수 강제"는 급수별 인원이 적어(남 A4/B1/C5/D6/왕초심8, 여 A3/B5/C8/D6/왕초심7) 오히려 같은 사람끼리 반복 심화. → **인접급수(±1) 허용**이 균형점.

변경(`core.jsx`):
- `PRESETS`에 `w_span` 추가. 밸런스=0, 동일 급수=20.
- `recommendMatch`: 4명 급수 폭(최고-최저 LEVEL_SCORE) 페널티. 폭0~1(동일·인접)=무페널티, 폭2+부터 `w_span*(폭-1)²`. 먼 급수(A-D) 매치 억제.
- 후보 윈도우: `w_span` 있으면 9→16으로 확대(비슷한 급수 4명 모일 기회↑).
- 쿨다운(최근 상대 회피)은 효과 미미·상태 추가 부담으로 미적용. 윈도우 확대만으로 통째 반복 충분히 낮음.

검증(실제 코드, 남복/여복+동일급수, 240경기): 인접급수까지 97.5% / **먼급수(A-D) 0.0%** / 같은 조 통째 연속 1.3% / 개인 경기수 17~18.

참고: "연속대전" 지표 정의 — 같은 조(상대 2명) 통째 재대전은 1~3%로 원래 낮음. "직전 상대 1명이라도 또"는 50% 안팎이나 멤버 일부만 겹치는 것이라 체감 다름. 인원 한계상 추가 감소는 어려움.
